The first completed CodeRabbit review requested deterministic coverage of two additional existing reader invariants. Six follow-up cases exercise both through the compiled SDK and CLI JSON/TOON routes. A child preload wraps real `fs.open`/descriptor `stat` calls solely to pause execution at an IPC barrier; it returns actual OS handles and stat results and does not replace SDK behavior. A separate parent process performs the real filesystem changes, then resumes the reader. No sleeps or FIFO writers establish ordering.

For growing input, the contract has exactly 65,536 bytes when the real descriptor stat completes. The parent appends one whitespace byte before the reader allocates and reads, and every route must emit `invalid_contract` instead of forecasting the valid 65,536-byte prefix. For pathname replacement, the parent renames the already opened regular file and creates a FIFO at its former pathname before classification. Every route must forecast the retained original descriptor, while the pathname remains a writerless FIFO. Both scenarios assert unchanged SDK-read tracker items and settings. Child deadlines, awaiting process closure in `finally`, and fixture cleanup also apply to these asynchronous tests.
